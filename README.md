# Системы сборки и тестирования v3

Система сборки нужна, чтобы автоматизировать сборку большого проекта. Хорошая система сборки позволяет собрать или установить проект за 1-2 команды, а также заново билдить только те файлы, которые были изменены после первой сборки. Последнее сильно сокращает разработку с компилируемыми языками.

Фреймворки тестирования типа xUnit облегчают тестирование (кто бы мог подумать), особенно модульное (unit). Они позволяют четко обозначить тесты, тест-сьюты, fixtures (код до и после тестов, например для аллокации и де-аллокации), и использовать различные проверки (assert). Хороший тестовый фреймворк также позволяет удобно посмотреть статистику прохождения тестов.

## Что используется здесь

Код в примере написан на C++, система сборки - cmake, фреймворк для тестирования - gtest. Это не единственные хорошие варианты, но они самые распространенные. В качестве компиляторов подойдут g++, clang++ или аналоги. Для msvc вам надо будет поменять флаги компиляции в файлах CMakeLists.txt

## Структура этого проекта

Здесь и на практике рекомендую представлять проект в виде библиотеки и консольного приложения, которое ее использует. В библиотеке реализовать логику, в коде приложения - использование этой логики.

В качестве структуры папок я предлагаю использовать pitchfork layout:
 - build/ - в эту папку будем собирать проект; при использовании системы контроля версий ее надо игнорировать
 - include/ - публичные заголовочные файлы библиотеки; именно их использует приложение
 - src/ - код библиотеки; код реализации (.cpp) и приватные заголовочные файлы, которое приложение напрямую использовать не может
 - app/ - код приложения; именно здесь присутствует исходник с функцией main - точкой входа программы
 - tests/ - название говорит само за себя, здесь тесты
 - CMakeLists.txt - корневой файл для системы сборки
 - README.md - вы здесь; readme-файлы поясняют назначение проекта, необходимые зависимости, процесс сборки и установки и тд

## К слову о зависимостях

Понадобятся cmake и gtest. Пример установки на debian/ubuntu:

```bash
sudo apt install -y cmake libgtest-dev
```

## Как пользоваться примером

1. Собрать и запустить приложение
2. Изучить файлы CMakeLists.txt
3. Собрать и запустить тесты
4. Изучить исходники тестов

### Как собирать пример на cmake

```bash
cd build
cmake ..
cmake --build .
```

В папке build сперва создаем файлы, которые будет использовать система сборки (cmake ..). Затем в этой же папке собираем проект (cmake --build .).

Далее запускаем собранное приложение.

```bash
<корень проекта>/build/app/main
```

### А где тесты?

Ответ в корневом CMakeLists.txt

### Как читать исходники?

Там все поясняют комментарии. Для ключевых понятий языка (кроме самого синтаксиса) указаны просто термины или ссылки, которые можно и нужно гуглить, если они вам не знакомы.
